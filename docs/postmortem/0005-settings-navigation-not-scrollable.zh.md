# 事故复盘（postmortem） 0005：设置面板的导航轨道裁掉了自身溢出，装上的分区无法到达

[English](0005-settings-navigation-not-scrollable.md) | 中文

Status: resolved upstream in `47ee6080` (`fix(web): allow overflowing settings navigation to scroll`); backported onto `dsh-v0.1.2-alpha.2`

## 摘要

设置对话框的分区导航轨道无法滚动。它的外层把面板高度固定成一个值并裁掉超出部分，而轨道内部没有任何元素承担溢出，于是只要已安装插件把注册的分区挤出面板，最后几行就永久不可达：既没有滚动条，也没有可供滚轮滚动的元素。它之所以流出去，是因为出厂的分区数量刚好放得下，也没有任何测试把轨道推到面板高度之外。可长期复用的教训是：一个高度固定、子列表长度可变的弹性容器必须明确指定溢出由谁承担，而验证这一点的检查必须**主动造出溢出**，不能依赖某次构建恰好只有几个分区。

## 概述

设置外壳渲染一个高度固定的模态面板（`height: min(800px, calc(100vh - 48px))`），分成左侧导航轨道与右侧内容列。轨道纵向堆叠一个标题和一列分区单元格，每个单元格对应一个注册的 `settings.section` 贡献：出厂客户端包贡献四个，其余每个提供设置页的已安装插件各贡献一个。

分区足够多时，列表比轨道更高，底部若干行被面板的 `overflow: hidden` 裁掉，且无法触及。在出厂分区数量下看不出任何异常，这正是它能通过评审的原因：该缺陷取决于用户装了多少插件，而不取决于构建出来的代码。另一个因素让这种失效看起来像是有意为之——面板的布局注释写着放不下的内容在 `.options` 里滚动，这对内容列成立，但对旁边的轨道悄悄不成立。

修复只有一条声明，给分区列表加 `overflow-y: auto`，因为在弹性布局里，非 `visible` 的溢出同时会把该条的自动最小尺寸归零。机制就这一句话：加这条声明之前，列表无法收缩到内容高度以下；而 `overflow-y: auto` 正是解除这个钳制的属性。

## 影响

插件贡献的设置页足够多的用户完全打不开最后几个分区：滚轮不行、键盘不行、对话框也没有提供任何可达手段。这些分区正是插件暴露自己配置的地方，所以实际后果是该插件变得无法配置，既不报错，也没有任何提示说明折叠线以下还有内容。

在本地 `0.1.2-alpha.2` 安装上实测（19 个已注册分区，视口 1440x800）：面板高 752 px，轨道列表需要 832 px，因此有 144 px 的单元格——最后三到四行——落在面板裁剪区之外。视口改为 1440x620 时，同一个列表丢失 324 px。

## 时间线

- 2026-08-30：`dsh-v0.1.2-alpha.2` 发布，轨道列表不承担任何溢出。
- 2026-09-20：上游 `47ee6080` 给分区列表加上 `overflow-y: auto`，并补了一个把视口压小以强行造出溢出的端到端检查。
- 2026-10-28：在本地 `0.1.2-alpha.2` 安装上复现（19 个分区，1440x800 下被裁 144 px），先用运行中服务端实际下发的字节核对，再把上游那条声明回移到本标签上，并以真实浏览器十条断言验证，其中包括「滚到底后最后一个单元格可点击」和「每个单元格仍保持 40 px 行高」。

## 根因

三条声明共同把内容藏了起来，而每一条单独看都是正确的：

```css
.panel { height: min(800px, calc(100vh - 48px)); overflow: hidden; }  /* 高度固定，裁剪 */
.nav { flex: none; display: flex; flex-direction: column; }           /* 不承担溢出 */
.navList { display: flex; flex-direction: column; gap: 4px; }         /* 不承担溢出 */
```

面板是确定高度的弹性行容器，轨道因此被拉伸到面板高度。轨道是列向弹性容器，其列表是一个 `overflow: visible` 的弹性子项，所以列表的自动最小尺寸取到内容高度：列表拒绝收缩、撑出轨道，面板的 `overflow: hidden` 再把这份溢出裁掉。整条链路上没有任何元素是滚动容器，浏览器既没有可挂滚动条的对象，也没有可接收滚轮增量的对象。

只加一条声明就能修好，原因是自动最小尺寸只在子项溢出为 `visible` 时生效：

```css
.navList { display: flex; flex-direction: column; gap: 4px; overflow-y: auto; }
```

有了 `overflow-y: auto`，该子项的自动最小尺寸归零，列表收缩进标题下方的剩余空间，内容在列表内部溢出，列表本身成为滚动容器。标题保持不动，只有单元格移动。在同一子项上显式写 `min-height: 0` 是等价做法；最终采用的修复依赖的是那个同时提供滚动的属性，所以一行就够。

## 为何所有防线都漏掉了它

- **失效规模随已安装插件增长。** 组件测试用少量合成分区挂载外壳，这些分区放得下面板。该缺陷需要分区数超过面板高度容量，所以在用户插件集变大之前，构建出来的代码没有任何地方是错的。
- **面板是刻意与内容无关的。** 固定高度本身是特性：内容自适应的面板会在每次点击导航时在手底下改变尺寸。同一个决定也意味着面板永远不会为了容纳更长的轨道而变高，所以轨道必须自己承担溢出。布局注释描述的是内容列的滚动，却被当成了两列的共同规格。
- **被裁剪的区域看起来就是一个短列表。** `overflow: hidden` 不产生滚动条、不产生滚动阴影、也不给 DOM 任何提示。在出厂分区数量下审阅这个对话框，看到的是一个整齐完整的列表。
- **没有任何断言检查可滚动性。** 端到端测试会打开对话框、切换分区，却从未检查轨道的几何，因此对测试而言「列表放得下」与「列表能滚动」无法区分。

## 已添加的防护措施

- 上游的修复带一个端到端检查：把视口设为 320x240 以保证溢出，然后断言轨道的 `scrollHeight` 大于 `clientHeight`、在轨道上滚动只移动轨道（其 `scrollTop` 增长，而标题的包围盒与内容列的滚动偏移保持不变）、以及最后一个单元格可命中并能选中其分区。
- 针对这套布局的回归检查必须自己造出它所测的溢出。用溢出的视口复现，而绝不用出厂分区数量复现，这条检查才有意义。
- 「容器高度固定」附带一项义务：说明溢出由谁承担。一个高度固定、子项数量或长度可变的弹性容器，必须指明哪个后代负责滚动，否则它就会裁剪。

## 教训

一个故意裁剪的布局，从外部看与一个意外丢失内容的布局无法区分。做裁剪这个决定时必须同时说明还有什么是可达的，而这条可达性主张需要一个能撑破容器的测试来支持——一个恰好放得下今天内容的容器，对明天的内容什么也证明不了。

## 回移说明

`dsh-v0.1.2-alpha.2` 早于上游修复，所以本分支原样携带上游那条声明（对分区列表的同一处单行改动，以及对面板布局注释的同一处更正），并附上本页文档。运行时验证用的是针对在线安装的无头浏览器脚本，而不是上游的端到端套件，因为那套件属于后来的布局：它的十条断言覆盖上游检查所确立的事实（溢出存在、轨道可滚动、标题保持固定、最后一个单元格能选中分区），并补充了行高与短视口两类情形。
